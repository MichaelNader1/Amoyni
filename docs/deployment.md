# Amoyni — دليل الرفع (Deployment Guide)

المشروع بالكامل HTML/CSS/Vanilla JS بدون أي Build خطوة، لذلك أي استضافة Static Hosting تكفي.

## Vercel (الأسهل)
1. ادفع المجلد لمستودع GitHub.
2. من [vercel.com](https://vercel.com) → New Project → اختر المستودع.
3. اترك إعدادات الـ Build فارغة (Framework: **Other**, Build Command: فارغ, Output Directory: `.`).
4. ملف `vercel.json` المرفق يهتم بإعادة التوجيه (routing) الأساسية.
5. بعد النشر، تأكد أن `config.js` يحتوي على القيم الحقيقية لمشروع Supabase (وليس القيم المحلية للتجربة).

## ترقية QR Attendance لمشروع قائم

قبل الترقية، إذا كانت هناك اجتماعات قديمة متعددة بحالة `active`، أغلقها يدويًا واترك اجتماعًا
واحدًا فقط. بعدها شغّل `supabase/migration_3_secure_qr_attendance.sql` مرة واحدة قبل نشر ملفات
الواجهة الجديدة. الترقية ترفض التنفيذ لو وجدت أكثر من اجتماع نشط، ولا تغلق بيانات قائمة بصمت.
هي لا تحذف سجلات حضور أو مستخدمين، لكنها تتطلب تسجيل الدخول مرة أخرى لإصدار session token موثوق.

## Netlify
1. اسحب وأفلت المجلد كامل في [app.netlify.com/drop](https://app.netlify.com/drop)، أو اربطه بـ Git.
2. Build command: فارغ. Publish directory: `.` (جذر المشروع).

## أي استضافة Static أخرى (GitHub Pages، Cloudflare Pages، إلخ)
فقط ارفع محتوى المجلد كما هو. لا يوجد `node_modules` مطلوب في وقت التشغيل — كل مكتبات
JavaScript (Supabase SDK، ماسح QR، الكونفيتي، مولّد QR) موجودة بالفعل داخل `assets/vendor/`.

## نقاط أمان مهمة قبل الرفع
- **لا تضع أبدًا** `service_role key` في `config.js` أو أي ملف داخل المجلد — فقط الـ `anon key`.
- تأكد أن `config.js` (بالقيم الحقيقية) غير مرفوع لمستودع عام إذا كنت لا تريد أن يرى الناس رابط
  مشروعك (القيم نفسها ليست خطيرة لأنها anon key محمي بالـ RLS، لكن يفضل التحفظ).
- غيّر كلمة مرور حساب الأدمن الافتراضي (`admin` / `ChangeMe123!`) فور أول تسجيل دخول.

## بعد الرفع
1. افتح `/admin/login.html` وسجّل الدخول وغيّر كلمة المرور.
2. من صفحة "الإعدادات" و"الدعوات" اضبط القيم حسب احتياج الخدمة الفعلي.
3. احذف بيانات الـDemo (الشباب التجريبيين، كود `WELCOME50`، حملة التبرع التجريبية، الاجتماع
   التجريبي) من لوحة الأدمن قبل الاستخدام الحقيقي.
